# Changelog

## 6.0.0

Библиотека написана заново под новое API `ticket.rzd.ru`. Прежний протокол
`pass.rzd.ru` с обменом идентификатором запроса больше не используется.
Совместимости с 5.x нет, порядок перехода описан в [docs/migration.md](docs/migration.md).

### Почему заново

Легаси-протокол требовал двух запросов на каждую операцию: сначала получить
`RID` и куки, выждать паузу, повторить запрос с ними. Отсюда шли жалобы на
непредсказуемые ответы — issue [#17](https://github.com/visavi/rzd-api/issues/17)
и [#23](https://github.com/visavi/rzd-api/issues/23). Новое API отдаёт данные
первым же запросом, без сессии, повторов и пауз, и при этом даёт данные, которых
в прежнем не было вовсе.

### Breaking

**Точка входа — `Rzd\Client` вместо `Rzd\Api`**, разбитый по ресурсам:
`trains`, `transfers`, `cars`, `routes`, `stations`, `prices`, `references`,
`aeroexpress`.

**Методы возвращают типизированные модели, а не строки JSON.** Полный ответ
сайта доступен через `Model::raw` и `Model::get()`, поэтому редкое поле не
требует правки библиотеки.

**Параметры передаются объектами запросов вместо массивов**, с проверкой до
обращения к сайту. Связанные запросы собираются из результатов предыдущих:
`CarSearch::forTrain($train)`, `RouteSearch::forTrain($train)`,
`CarSchemeSearch::forCar($car, $train)` — переносить коды станций и время
отправления руками больше не нужно.

**HTTP-клиент передаётся снаружи**, любая реализация PSR-18. Guzzle убран из
обязательных зависимостей. Таймаут, прокси, повторы и логирование настраиваются
в клиенте, а не в библиотеке.

**Поиск туда-обратно переименован в `searchReturn()` и работает иначе.** Прежний
`trainRoutesReturn` искал пару маршрутов одним запросом с параметром
направления. Новое API так не умеет: параметры второй даты оно игнорирует, а его
собственная страница туда-обратно отправляет два независимых запроса. Метод
делает эти два запроса за один вызов и возвращает `RoundTrip` с полями `forward`
и `back` вместо одного ответа с двумя блоками.

**Удалены `setRetryDelay`, `setRetryLimit` и `setHandler`.** Первые две
относились к обмену идентификаторами, которого больше нет. Подмена транспорта
делается передачей подставного PSR-18 клиента.

**Настройки неизменяемы:** `Config` принимает значения через конструктор,
копии дают `withLanguage`, `withUserAgent`, `withHeaders`.

**Требования подняты:** PHP 8.2 вместо 8.0.

### Added

**Поиск с пересадками.** `Transfers::search()` строит цепочки рейсов там, где
прямых поездов нет: считает ожидание между рейсами и переезды между вокзалами
города. Поиск мультимодальный, состав видов транспорта задаётся через
`TransportProvider`. Прежнее API умело это только через отдельный параметр
`md` сырого запроса, без разбора ответа.

Города задаются идентификаторами узлов сайта, а не кодами станций, поэтому
запрос собирается из подсказок: `TransferSearch::forStations($from, $to, $date)`.
В каждый рейс цепочки сайт вкладывает полный ответ обычного поиска, поэтому
вагоны и цены доступны сразу — `Trip::train()`.

**Номера свободных мест.** `Car::freePlaces` строкой как отдаёт сайт,
`Car::placeNumbers()` числами, `Car::compartments` — раскладка по купе.
Прежнее API таких данных не давало.

**Схемы вагонов.** `Cars::scheme()` отдаёт идентификатор и варианты чертежа,
`Cars::schemeImage()` — сам чертёж в SVG, включая второй этаж двухэтажных
вагонов. `Cars::images()` — фотографии салона.

**Календарь цен и наличия.** `Prices::availability()` — даты, на которые между
станциями есть места, `Prices::calendar()` — минимальные цены по датам с
разбивкой по типам вагонов. Раньше это можно было узнать только перебором
запросов по дням.

**Справочник тарифов** — `References::tariffs()`, около полутора сотен тарифов
с условиями применения.

**Конфигурация сайта** — `References::appConfig()`.

**Популярные города и поиск по идентификатору узла** — `Stations::popular()`,
`Stations::byNodeId()`.

**Карты и абонементы** — `References::cards()`, около сотни записей: скидка в
процентах либо число поездок, типы вагонов и классы обслуживания, сроки продажи
и поездки, правила возврата и обмена.

**Календарь продажи** — `Prices::saleCalendar()`. Отвечает на другой вопрос, чем
`availability`: не где есть места, а до какой даты вообще открыта продажа по
направлению. Сайт отдаёт около тринадцати месяцев вперёд.

**Аэроэкспресс** — `Aeroexpress::tariffs()`, тарифы на поездку в аэропорт с
условиями применения и списком принимаемых документов.

**Больше данных о поезде:** бренд, категория, время в пути в минутах,
расстояние в километрах, перевозчики, услуги, признак двухэтажного состава.

**Больше данных о маршруте:** местное и московское время каждой остановки,
стоянка в минутах, сутки от станции формирования, разница с московским
временем.

**Иерархия исключений** с общим интерфейсом `RzdException`: `TransportException`
для недоступности сайта, `ForbiddenException` для блокировки запроса,
`ApiException` с кодом ответа и телом, `MalformedResponseException`,
`InvalidArgumentException`.

### Прочее

Тесты переписаны на подставной PSR-18 клиент, покрытие `src` полное — 100%
классов, методов и строк. Живые запросы вынесены в группу `live`, исключённую
из обычного прогона и из CI: сайт принимает их только с российских адресов.

```sh
composer test
RZD_PROXY=socks5://127.0.0.1:1080 composer test:live
```

Прогон в GitHub Actions на PHP 8.2, 8.3, 8.4 и 8.5. Примеры переписаны по
методам и запускаются из консоли. Описание эндпоинтов сайта собрано в
[docs/endpoints.md](docs/endpoints.md). Устаревшие скриншоты удалены: они
показывали формат ответа прежнего API.

## 5.0.0

Последняя версия на протоколе `pass.rzd.ru`.

### Breaking

**`stationCode()` перешел на другой эндпоинт и отдает больше данных.** Старый
`pass.rzd.ru/suggester` перестал работать: на любой запрос отвечает `200` с пустым
телом и заголовком `application/json`. Метод переведен на `ticket.rzd.ru/isdk/suggests`.

Ключи `station` и `code` на месте, но названия станций приходят в исходном
регистре, а не капсом, и добавились новые поля:

```php
// было
[['station' => 'ЧЕБОКСАРЫ', 'code' => 2060620]]

// стало
[[
    'station'  => 'Чебоксары',
    'code'     => '2060620',
    'region'   => 'Российская Федерация',
    'type'     => 'Город',
    'timezone' => 'Europe/Moscow',
    'codes'    => ['Railway' => '2060620', 'Cbdpr' => '5389', 'Bus' => '...', 'Avia' => 'CSY'],
    'stations' => ['2060206', '2060620', '2060899'],
]]
```

`codes` содержит коды смежных видов транспорта, включая пригородные перевозки,
`timezone` нужен для корректной даты отправления с учетом пояса станции.
Параметр `compactMode` новым эндпоинтом не используется, добавлен алиас `Query`
для `stationNamePart`.

**`trainRoutes()` возвращает данные направления, а не голый список поездов.**
Список переехал в ключ `list`, рядом с ним появились `from`, `where`, `date`,
`state`, `msgList` и `noSeats`. Раньше отсутствие мест и отсутствие поездов были
неотличимы, оба давали пустой массив.

```php
// было
$routes = json_decode($api->trainRoutes($params));
foreach ($routes as $train) { ... }

// стало
$routes = json_decode($api->trainRoutes($params));
foreach ($routes->list as $train) { ... }
```

**`trainRoutesReturn()` отдает в `forward` и `back` такие же блоки**, как
`trainRoutes`, а не списки поездов. Поезда лежат в `forward->list` и `back->list`.

**`trainCarriages()` отдает больше ключей.** Добавились `train` (данные поезда
без дублирования списка вагонов), `companyTypes`, `childrenAge`,
`motherAndChildAge`, `foodIconTips`, `psaction` и `partialPayment`. Все они
приходили от сайта и раньше, но отбрасывались. Прежние `cars`, `functionBlocks`,
`schemes` и `companies` не изменились.

**Исчерпание попыток теперь выбрасывает исключение.** Если сайт десять раз подряд
ответил идентификатором вместо данных, код возвращал последний такой ответ, и
дальше методы `Api` разбирали его как обычные данные — на выходе получался объект
с пустыми ключами (issue #23). Теперь бросается `RuntimeException` с текстом
`Data not received, request id limit exceeded!`.

### Added

**`Config::setRetryLimit()`** — число повторов, пока сайт отдает идентификатор,
по умолчанию прежние 10.

**`Config::setRetryDelay()`** — пауза перед повторным запросом с полученным `RID`,
по умолчанию прежняя секунда. Раньше была захардкожена.

**`Config::setHandler()`** — подмена транспорта Guzzle, нужна для моков в тестах.

**Браузерный `User-Agent` по умолчанию.** Без него `ticket.rzd.ru` отвечает `403`.

### Fixed

**Идентификатор запроса не обновлялся между итерациями.** Оператор `+=` не
перезаписывает существующий ключ, поэтому на повторных проходах цикла уходил
самый первый `rid`.

**Ветка `REQUEST_ID` была нерабочей.** `getRid()` искал только ключи `rid` и `RID`,
поэтому ответ с таким статусом всегда завершался исключением `Rid not found!`.

**Сообщение об ошибке от сайта терялось.** Код читал `$response->message` у
PSR-7 объекта, где такого свойства нет, а `??` глушил это молча. Сообщение
лежит в теле ответа, причем в ключе `error`, а не `message` — так приходит,
например, `SESSION_EXPIRED` из issue #17.

**Убрана несуществующая опция Guzzle** `'cookie' => true` в конфиге клиента.

### Changed

Guzzle поднят до `^8.0`, PHPUnit до `^9.6.33` — в более ранних версиях
уязвимость CVE-2026-24765.

Тесты переписаны на моки и не обращаются к сети, покрытие `src` полное. Проверка
реальных ответов сайта вынесена в группу `live`, которая исключена из обычного
прогона и из CI.

Удалены `Dockerfile`, папка `controllers` и `docs/auth.md`, описывавший вырезанный
в 3.0 класс `Auth`. Механика RID-обмена вынесена из readme в `docs/protocol.md`.
