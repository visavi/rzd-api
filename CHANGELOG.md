# Changelog

## Unreleased

### Breaking

**`stationCode()` перешел на другой эндпоинт и отдает больше данных.** Старый
`pass.rzd.ru/suggester` перестал работать: на любой запрос отвечает `200` с пустым
телом и заголовком `application/json`. Метод переведен на `ticket.rzd.ru/isdk/suggests`.

Ключи `station` и `code` на месте, но названия станций приходят в исходном
регистре, а не капсом, и добавились новые поля:

```php
// было
[['station' => 'ЧЕБОКСАРЫ', 'code' => 2060620]]

// стало
[[
    'station'  => 'Чебоксары',
    'code'     => '2060620',
    'region'   => 'Российская Федерация',
    'type'     => 'Город',
    'timezone' => 'Europe/Moscow',
    'codes'    => ['Railway' => '2060620', 'Cbdpr' => '5389', 'Bus' => '...', 'Avia' => 'CSY'],
    'stations' => ['2060206', '2060620', '2060899'],
]]
```

`codes` содержит коды смежных видов транспорта, включая пригородные перевозки,
`timezone` нужен для корректной даты отправления с учетом пояса станции.
Параметр `compactMode` новым эндпоинтом не используется, добавлен алиас `Query`
для `stationNamePart`.

**`trainRoutes()` возвращает данные направления, а не голый список поездов.**
Список переехал в ключ `list`, рядом с ним появились `from`, `where`, `date`,
`state`, `msgList` и `noSeats`. Раньше отсутствие мест и отсутствие поездов были
неотличимы, оба давали пустой массив.

```php
// было
$routes = json_decode($api->trainRoutes($params));
foreach ($routes as $train) { ... }

// стало
$routes = json_decode($api->trainRoutes($params));
foreach ($routes->list as $train) { ... }
```

**`trainRoutesReturn()` отдает в `forward` и `back` такие же блоки**, как
`trainRoutes`, а не списки поездов. Поезда лежат в `forward->list` и `back->list`.

**`trainCarriages()` отдает больше ключей.** Добавились `train` (данные поезда
без дублирования списка вагонов), `companyTypes`, `childrenAge`,
`motherAndChildAge`, `foodIconTips`, `psaction` и `partialPayment`. Все они
приходили от сайта и раньше, но отбрасывались. Прежние `cars`, `functionBlocks`,
`schemes` и `companies` не изменились.

**Исчерпание попыток теперь выбрасывает исключение.** Если сайт десять раз подряд
ответил идентификатором вместо данных, код возвращал последний такой ответ, и
дальше методы `Api` разбирали его как обычные данные — на выходе получался объект
с пустыми ключами (issue #23). Теперь бросается `RuntimeException` с текстом
`Data not received, request id limit exceeded!`.

### Added

**`Config::setRetryLimit()`** — число повторов, пока сайт отдает идентификатор,
по умолчанию прежние 10.

**`Config::setRetryDelay()`** — пауза перед повторным запросом с полученным `RID`,
по умолчанию прежняя секунда. Раньше была захардкожена.

**`Config::setHandler()`** — подмена транспорта Guzzle, нужна для моков в тестах.

**Браузерный `User-Agent` по умолчанию.** Без него `ticket.rzd.ru` отвечает `403`.

### Fixed

**Идентификатор запроса не обновлялся между итерациями.** Оператор `+=` не
перезаписывает существующий ключ, поэтому на повторных проходах цикла уходил
самый первый `rid`.

**Ветка `REQUEST_ID` была нерабочей.** `getRid()` искал только ключи `rid` и `RID`,
поэтому ответ с таким статусом всегда завершался исключением `Rid not found!`.

**Сообщение об ошибке от сайта терялось.** Код читал `$response->message` у
PSR-7 объекта, где такого свойства нет, а `??` глушил это молча. Сообщение
лежит в теле ответа, причем в ключе `error`, а не `message` — так приходит,
например, `SESSION_EXPIRED` из issue #17.

**Убрана несуществующая опция Guzzle** `'cookie' => true` в конфиге клиента.

### Changed

Guzzle поднят до `^8.0`, PHPUnit до `^9.6.33` — в более ранних версиях
уязвимость CVE-2026-24765.

Тесты переписаны на моки и не обращаются к сети, покрытие `src` полное. Проверка
реальных ответов сайта вынесена в группу `live`, которая исключена из обычного
прогона и из CI:

```sh
vendor/bin/phpunit                                              # моки
RZD_PROXY=socks5://127.0.0.1:1080 vendor/bin/phpunit --group live
```

Удалены `Dockerfile`, папка `controllers` и `docs/auth.md`, описывавший вырезанный
в 3.0 класс `Auth`. Механика RID-обмена вынесена из readme в `docs/protocol.md`.
